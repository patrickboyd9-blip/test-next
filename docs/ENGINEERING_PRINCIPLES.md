# Engineering Principles

## 1. Quality First

Working software is more important than quickly written software.

Never sacrifice maintainability for speed.

---

## 2. Build Like a Product

Every feature should feel production-ready.

Avoid placeholder implementations unless explicitly requested.

---

## 3. One Source of Truth

Avoid duplicated business logic.

Prefer shared components and reusable abstractions.

---

## 4. Keep It Simple

Choose the simplest solution that satisfies the requirements.

Avoid unnecessary complexity.

---

## 5. Ship in Milestones

Every milestone must:

- Build successfully
- Run locally
- Pass the Release Checklist
- Be committed and tagged before starting the next milestone

---

## 6. Preserve Existing Functionality

Never break an existing feature while implementing a new one.

Regression testing is required before every release.

---

## 7. UI Philosophy

The interface should feel:

- Calm
- Premium
- Modern
- Minimal
- Fast

Animations should support the experience, never distract from it.

---

## 8. AI Philosophy

AI should:

- Reduce work
- Increase confidence
- Never surprise the user
- Explain its reasoning
- Offer recommendations instead of making irreversible decisions

---

## 9. Documentation

Every major feature should include:

- PRD
- Documentation
- Milestone update
- Release Checklist completion

---

## 10. Definition of Done

A feature is not complete until:

- Implementation finished
- Documentation updated
- Build passes
- Dev server runs
- Browser verified
- Release Checklist completed
- Git committed
- Version tagged
